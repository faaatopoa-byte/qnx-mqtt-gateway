# Tes Beban Gateway Mosquitto QNX — 28 Nov 2026

**Perintah Faa:** "test berat aja dicoba" — cari tahu gateway kuat sampai berapa sebelum drop.
**Image yang dites:** SDP 8.0.6 `minimal-ifs-806/minimal-ifs.bin` (21.277.940 B, yang sudah lolos boot test 600 detik 27 Nov).
**Cara tes:** boot image di QEMU (RAM 256 MB), lalu kirim beban dari DALAM guest lewat konsol serial
(mosquitto_pub/sub bawaan image, 127.0.0.1:1883). Host tidak bisa mencapai broker lewat TCP karena image
tidak punya ifconfig/dhcp — jadi beban dijalankan dari dalam guest, menguji broker + plugin gateway yang sama.
**Kode/repo/Devpost TIDAK diubah** — ini tes saja.

## Vonis: titik patah TIDAK ketemu

Gateway lolos semua level sampai **20.000 pesan dalam satu burst, 0 drop**.
Jadi jawabannya: **kuat sampai minimal 20.000 pesan sekaligus — di atas itu belum dites, bukan berarti di situlah batasnya.**
Kecepatan yang terukur di sini ~150–185 pesan/detik — itu **batas bawah**, bukan batas gateway:
kecepatan itu dibatasi emulasi QEMU + broker yang log tiap pesan ke konsol serial, bukan oleh Mosquitto-nya.
Di perangkat QNX beneran pasti jauh lebih cepat.

## Sumber daya yang dipakai (run 6)

- QEMU di host: RAM ~365–380 MB (guest 256 MB + overhead)
- RAM host tersedia: terendah ~352 MB pas level 8 (tidak pernah kena garis darurat 80 MB, tidak ada OOM)
- Beban CPU host: load1 ~1,2–1,4 pas beban jalan
- Delphi tidak diganggu; tidak ada kerjaan berat lain yang jalan (jadi tidak ada yang perlu dihentikan)
- Setup: install ulang QEMU 8.2.2 via apt (~12 menit, QEMU hilang karena VM restart)

## Yang belum dites (jujur)

- Perangkat QNX beneran — semua ini di QEMU (mesin tiruan), jadi angka kecepatan itu batas bawah
- Kipas ke banyak subscriber sekaligus (baru 1 subscriber per tes)
- Pesan QoS 1/2 (yang dites QoS 0 — kirim-sekali, kalau hilang tidak ketahuan dari protokol, makanya dihitung manual ujung-ke-ujung)
- Beban di atas 20.000 pesan sekaligus

## Perjalanan tes (biar tidak diulang salahnya)

- Run 1: gagal — shell guest menolak loop `for (( ))` (bukan ksh93) + tidak bisa bikin pipe
  ("sh: can't create pipe" — tidak ada pipe manager di image minimal).
- Run 2: gagal — pipe diganti file, tapi loop `while` tetap pakai pipe (`while...done | pub`).
- Run 3: level 1 & 7 lolos (100/100), tapi level 2 kebaca "drop 1000" — ternyata salah baca:
  hitungan diambil sebelum subscriber selesai; log broker membuktikan 1.000/1.000 beneran masuk.
- Run 4: gagal — log serial pakai CRLF, angka kebaca "100\r" bikin error aritmatika.
- Run 5: level 4 kebaca "7.008/10.000" — lagi-lagi hitungan di tengah jalan; forensik log broker:
  broker terima 10.000, teruskan 10.000, subscriber keluar normal sesudah 10.000. Level 4 sebenarnya lolos.
- Run 6: driver diperbaiki (tunggu subscriber selesai dulu baru hitung + `grep -o` anti `\r`) —
  **semua level lolos, DRIVER_EXIT=0.**
